# Security research and publication

Detailed security reports, vulnerability mechanics, unpublished binary offsets,
raw captures, firmware binaries and real device/session identifiers must remain
in owner-controlled local storage outside this repository.

Public issues, pull requests, comments and documentation may contain sanitized
engineering summaries. Use synthetic identifiers in examples and tests. Preserve
the full private evidence and provenance before replacing public identifiers.

Before publishing, review the complete commit history being pushed, not only the
latest diff. An unpublished sensitive commit must not remain an ancestor of the
public branch. Never attach raw evidence to public CI artifacts or discussions.

External disclosure of detailed security findings requires the owner's explicit
authorization. Do not send them to another service, repository or manufacturer by
default. Removing current text does not erase previously published Git history,
edit history, caches or third-party copies.
